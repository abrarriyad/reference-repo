# Design conventions for report.html

The report is generated by `scripts/novel-characters.mjs render --html`, with all styling inlined inside `renderHtml()`. **Change styles in that one place only**; do not start a separate template.

This document records why it looks the way it does, so later changes do not turn it back into a generic card wall.

## What it is

Not a marketing page, but a **production character bible**. The reader is the person who will take these prompts and actually generate images and record voices. The page has one job: **let someone grab the right prompt fast, while believing the profiles are grounded in the source.**

Every design decision follows from that sentence.

## Multilingual

The UI strings live in the `STRINGS` table in `novel-characters.mjs`, with `zh` / `en` / `ja` built in. To add a language, add a key — **do not hard-code Chinese into the template**; the `t` that `renderCharacter` / `renderGraph` / `renderHtml` receive is that table.

For a language not in the built-in table, the skill translates a copy on the spot, puts it into `cast.json`'s `ui`, and `strings()` merges it in. So supported languages are not limited by the built-in table. Function templates (`docTitle` / `counts` / `graphCounts` and the like) **do not accept `ui` overrides**; an unknown language code falls back to the `en` skeleton, though `<html lang>` still carries the actual language code.

## Skeleton

```
┌─ top bar 60px ──────────────────────────────────────────┐
│ book title   [search]                  character bible · count │
├──────────────┬──────────────────────────────────────────┤
│ left rail 400px │ main area max-width 1500px                │
│ story summary (three lines) │                            │
│ ▸ relationship map │   ← map and character detail are mutually exclusive; only one shows │
│ character 01 … │                                          │
│ character 02 … │  01 name  protagonist  one-liner         │
│ character 03 … │  ┌──────────────┬──────────┐             │
│              │  │ sheet + profile │ info card │  1fr / 500px │
│              │  ├──────────────┴──────────┤             │
│              │  │ source evidence           │             │
│              │  ├──────────────┬──────────┤             │
│              │  │ image prompt   │ voice prompt │  1fr / 1fr │
```

The left rail is `position:sticky`, full height and scrolling; the main area shows only one `.char` at a time with `display:block`.

**Breakpoints**: `.shell` collapses to one column at 1080, `.upper` at 1240, `.prompts` at 900, `.graph-body` at 1100.

## Four rules that must not be broken

### 1. Two type domains

Chinese print typography already makes this division; just use it:

| Font | Register | Used for |
| --- | --- | --- |
| **Songti (serif)** `--serif` | Narrative — about the story | Book title, character name, one-liner, **story summary**, **source quotations**, node names in the map |
| **Heiti (sans)** `--sans` | Analytical — about the character | Profile body, field labels, UI, relationship text in the map |
| **Monospace** `--mono` | Machine input | English prompts, numbering |

The only thing genuinely copied verbatim from the source is `.source blockquote`, which additionally carries a rust-red bar — **that bar is the only marker of "this is the source"**; do not use it to decorate the summary or the one-liner.

This is what distinguishes this report from any character-card generator; do not unify it into a single font.

All system fonts, **no external fonts allowed** — the report must open offline by double-click.

### 2. Restrained on screen, fully expanded on paper

On screen you see one character at a time, prompts collapsed in `<details>`, the summary kept to three lines. **But `@media print` forces everything open**: all characters, all prompts and the relationship map must print.

This is a deliberate trade-off: an early version tiled four characters into a card wall, which looked full but read as nothing on one screen. Collapsing is so the current character can be read through, not to hide things — so on paper it must be a complete copy.

When changing anything to do with collapsing, **change the print block along with it**; the self-test has an assertion watching it.

### 3. Inferred markers must be highlighted

`（推断）` and `(inferred)` are automatically wrapped by `marked()` into `<span class="inf">` with a pale rust-red background. All four forms — half-width / full-width × Chinese / English — must be recognised.

This is the report's signature detail. The tool's core promise is "which parts are grounded in the source and which were added to make it usable", and making that visual is more useful than writing it in the docs. The footer carries a note too.

### 4. Self-contained

**No external resources allowed** — no CDN scripts, no external fonts, no remote images. The relationship map is hand-written inline SVG rather than d3, and this rule is what forced that. The self-test watches it from both sides (it checks that the output contains no `<script src>`, and also that the regex itself catches something, so it is never a test that is always true).

## Colour

Cold grey stock + rust-red seal. **Red is used only where it relates to the source and for the current selection**: the quotation bar, the protagonist tag, the chords lit up in the map. Do not use it as a general accent colour.

| token | value | Use |
| --- | --- | --- |
| `--paper` | `#eceded` | Cold grey stock, not warm cream |
| `--panel` | `#f5f6f5` | Prompt blocks, info card, map canvas |
| `--side` | `#e4e6e3` | Left rail |
| `--ink` | `#191d21` | Blue-black, not pure black |
| `--seal` | `#8a3324` | Rust red |
| `--seal-soft` | `#8a332412` | Background for inferred markers, and for the selected row in the map |

**There is no dark mode.** The model sheet is white stock and the report is cold grey stock; inverting both together makes the sheet look pasted on.

## Relationship map

A panoramic view, mutually exclusive with character detail, shown when `.main.gmode`.

**The layout is computed in Node and written into the SVG**; the browser side only adds the `hot` / `dim` classes. Same reason as above — no libraries.

- Circular layout, radius following headcount: `max(130, min(260, 40 + n*14))`, with 110 on both sides reserved for names
- Chords are quadratic Béziers, control point pulled 0.35 toward the centre. Straight lines blur into a net when there are many people
- Node size is tiered by `importance`; protagonists are solid rust red
- Every node carries a **transparent hit area with r=24** (`.ghit`). The visible dot is only about ten-odd pixels, and without this layer the clicks are imprecise

⚠️ **The hit area and the visible dot must each have their own class** (`.ghit` / `.gdot`). If both are written as `circle`, `.gnode.lead circle` will stain the hit area into one big red block too.

⚠️ **Relationship text is offset along the chord by index** (`t = 0.5 + ((i%3)-1)*0.14`); do not put them all at t=0.5. Between two characters facing each other, the chord's midpoint is exactly the centre, and putting them all at the midpoint piles them into one lump. The offset moves the text; the chord itself does not move.

Relationship text is truncated to **6 characters**, with the full text in `<title>`. The canvas is only 480 units wide, so a 12-character label eats 27% of it and two adjacent labels overlap directly. Edges ≤ 14 are labelled by default; beyond that they collapse by default, with a toggle at the top; **the hovered edge must still show while collapsed**.

## Export JSON

What the button in the top bar downloads **is exactly the shape of `cast.json` itself**, not some separate export format. This is a contract: an external tool must be able to edit it and feed it straight back into `render`, and it must still pass `validate`; the self-test watches this.

The data is embedded as `<script type="application/json" id="cast-data">`, and clicking export just wraps it in a Blob and downloads it — **no network request**.

⚠️ **`<` in the JSON must be turned into `<`.** A single `</script` in the body can truncate the data block early. `<` in JSON can only occur inside string values, so a global replace is safe.

⚠️ **`URL.revokeObjectURL` must not be called immediately after `a.click()`.** Safari will revoke the blob before the download has finished reading it, and what the user saves is an empty file. Revoke it later.

## One copy button per prompt block

This cannot be dropped. Currently 7 per character: image local/EN, sheet EN, negative, voice local/EN, the whole JSON. Characters with a sheet get one more, "copy image" — what is copied is **the image itself**, not the path, and non-PNG is first transcoded through a canvas (Safari only accepts `image/png`). The self-test watches this count.

## Quality floor

- Responsive down to phones (every multi-column layout has a breakpoint that collapses to one column)
- Keyboard focus visible (`.copy` / `.rost` / `.gnode` / `.grow` all have `:focus-visible`)
- SVG `<g>` is not a native button; Enter/Space must be wired up by hand
- `prefers-reduced-motion` turns off all animation and smooth scrolling
- `@media print` hides the top bar and left rail, expands all content, and keeps entries from breaking across pages
- Character data is model-generated, **always escaped with `esc()`** before being assembled into HTML; `marked()` already escapes internally, so do not wrap it again
