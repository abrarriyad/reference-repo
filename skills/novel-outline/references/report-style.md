# Design conventions for the outline report

The report is generated by `scripts/novel-outline.mjs render --html`, and all styling is inlined in `renderHtml()`. **Change styling in that one place only.**

## What it is

A **single-page report for industry review**: readers use it to decide whether to cut and whether to prepare for production. Page width 1600, everything laid flat so Cmd+F works, no sidebar, no collapsing. The visual language is the same as novel-characters: cool-grey stamp paper + rust-red seal marks.

## Block order (deliverable first, archive after)

```
Header      Title · parameter line · quality-gate badge (13/13) · export JSON
KPI band    Six stat cards: total episodes / beats / cast tiers / main scenes / generation difficulties / adaptation degree
(Problem banner)  Appears only when a quality gate has not passed, listing each one
01 Beat rhythm   Chart/table tab: timeline by default, switch to the detail table to see setup and payoff
02 Episode overview  Three-column cards (adaptive from 430px), showing only the first three episodes by default:
             fade at the bottom + "▾ Expand all N episodes"; one click expands everything and it does not collapse again; with ≤3 episodes there is no collapse
03 Scene overview  Full row, multi-column card grid (adaptive from 380px)
04 Key decisions  The three things signed off: which line was cut / which people were merged / in which episode the big reveal lands
05 Per-episode scheduling matrix  Full row — a 60-episode × 25-character matrix naturally takes the full width
06 Asset-volume conversion
07 Cast table
08 Adaptation notes  One-sentence core + four tables for keep / cut / merge / risks (evidence in 「」 quotation style)
09 Quality gates   Full ✓/✗ checklist
```

Putting the adaptation notes last is deliberate: they are the archive of "why it was adapted this way", not a deliverable to read every time.

**Collapsed on screen, fully expanded on paper**: tabs are only on-screen storage; in `@media print` both panels print, episodes are all expanded, and the tab strip and expand button are hidden. When changing collapse-related styles, change the print section too; the self-test has assertions watching it.

## Chart conventions (set by the dataviz method)

All single-hue, with **the colors run through the validator**: big reveal `#8a3324`, regular beat `#c56a4e`, passing all six checks on the panel background color. All inline SVG/CSS, **no libraries imported**.

### Key decisions (04)

A three-column card. The cut-line / merge-people lists come from `adaptation.cut/merge`; **the character-slot counts, the lead-group list and the big-reveal list are computed**. The optional `adaptation.cutNote / mergeNote` are conclusion sentences written by the model ("this means…"), on a rust-red background. The big-reveal list carries "first / finale" markers at its first and last entries.

### Beat rhythm (01, chart/table tab)

A story timeline: a horizon line with beats as nodes on the axis (big reveals r9 filled, regular r6, with a 2px panel-color outline ring), each node labeled with type + a setup excerpt, **labels alternating above and below to avoid collisions**, flipping to the opposite side when one episode has several beats. **Gaps are marked directly on the axis** ("— n-episode gap —"), and a gap exceeding `maxBeatGap` turns rust-red — a violation shouts for itself on the chart. Beyond 20 episodes it wraps at 20 episodes per row.

⚠ **The episode ticks must be drawn last** — they carry a panel-color underlay (`paint-order:stroke`) so they stay readable over a node's vertical line; if drawn first they get covered by the line.

### Per-episode scheduling matrix (05)

Characters + scenes in one grid, and **reading one column vertically gives that episode's requirements list** (who must appear, where to shoot). Character cells dark rust-red, scene cells light rust, with a band row "Scenes" separating them. One-off scenes carry a ⚠ in the total column, with the reuse plan in a footnote. Cell width shrinks with episode count (≤20 episodes 26px / ≤40 episodes 20px / ≤60 episodes 16px / more 12px), and overflow scrolls horizontally.

⚠ **The matrix and the scene overview must each take a full row; do not put them side by side.** Side by side looks good on a small sample, but at real scale (60 episodes × 25 characters + 12 scenes) the matrix eats all the width and the scene cards are squeezed to a sliver. Also, when a grid holds a scroll container whose content is too wide, the column width must use `minmax(0,1fr)` — grid items default to `min-width:auto` and get blown out by the content.

### Scene overview (03)

One card per scene: **light-grey episode numbers** at the top right (consecutive ones written together as `1–6`, discrete as `1 · 6`, too scattered reported as a count only, see `fmtEps`), a thin bar of appearance episodes, the **beats carried** (computed: beat placement × scene appearance episodes), and for main scenes the list of characters appearing / for one-off scenes the reuse plan (rust-red). **No share rings** — proportion does not drive decisions; which episodes they land in does.

### Asset-volume conversion (06)

A plain table. Three character tiers + scene environments + generation difficulties, all converted by `computeAssets`, with the model writing not a word.

## Quality gates

The header badge is always shown (passing green, failing red); when any fail, a **problem banner** pops up under the KPI band listing each one; 09 at the end is the full checklist. ✓/✗ are computed by `gateReport()` at render time and baked into the page, **not a model self-assessment**. Failing does not stop rendering — checkup mode exists precisely to lay the problems out.

## UI copy

All gathered in the `T` table; **do not scatter strings into templates**. Chinese copy avoids single-character words (write the full words for keep / cut / merge, not a single character each). v1 is Chinese only; to add a language, swap `T` for a table looked up by lang.

## Export JSON

A header button; the download **is outline.json verbatim** — embedded in `<script type="application/json" id="outline-data">`. Two pitfalls: `<` in the JSON must be escaped as `<` (so `</script` cannot truncate it); `revokeObjectURL` must be called late (so Safari does not jump the gun and save an empty file).

## Quality floor

- Import no external resources; it opens offline with a double-click, and the self-test watches both sides
- The outline data is model-generated, and is always escaped with `esc()` before being joined into HTML
- `@media print`: hide the export button, never break a card across pages
- `prefers-reduced-motion` turns off animation
