## character-refs

Input a character description, output a set of character reference images — **the character can come from anywhere**: a novel adaptation, a story you made up, a person who just occurred to you. **One front full-body anchor, and every other image references only this anchor.**
Used as reference images for video models (H3 / Wan / Seedance), and also for people to look at.

`{baseDir}` = the directory this file is in. The script is `{baseDir}/scripts/character-refs.mjs`, zero dependencies, run directly with `node`.

**This is the only skill in the repository that actually generates images.** The other skills deliver only prompts, because the model and art style can only be decided at the moment of image generation;
this skill is "that moment" — the model is chosen by the user in Step 0, and the art style is chosen when creating the character (anime by default, with a realistic preset as well, and a custom style can be attached).

### Core rules (understand them before acting)

- **A set of images has only one root: the front full-body anchor.** Only it is text-to-image; everything else is "anchor + one edit instruction".
  The three kinds of details — hair, face and collar — additionally attach the confirmed front headshot. Images no longer reference one another —
  so if any one image comes out bad, regenerating just that one is enough, with no cascade.
- **Tiers, generating up to tier two by default**:

  | Tier | Contents | When to generate |
  | --- | --- | --- |
  | 1 | Front full-body (anchor) | Always, the first image |
  | 2 (default) | Front headshot, 90° profile (facing the right side of the frame), back | Generated in full by default |
  | 3 | Detail images (at most 8): those the user names, the places that make the character most recognizable; if none, the defaults — hair / hair ornament, collar, cuff, shoes | When there are accessories or garment close-ups |
  | 4 (not generated by default) | 45° headshot (facing the left side of the frame) | When the user explicitly asks |

  H3 test result: given only the front full-body, the clothing and the back view are right but the face drifts; **add a headshot and the face comes closest**. So tier two is generated in full by default.
  If you want only the anchor (for example to see the look first): `gen <asset.json> --tier 1`.
- **The model is not locked**: the anchor and the derived images may use different models, and regenerating a single image may switch models as well. Consistency comes from "the same anchor image",
  not from "the same model" (found in testing: a Qwen anchor + GPT derived images, a GPT anchor + Qwen derived images, and mixing within one set all connect up).
  Each image records its own model, and mixing within a set is only flagged in the report.
- **Only three things are frozen**: the anchor file (sha256), the art-style snapshot, and the text-description fingerprint. If any of them changes,
  the images depending on it are marked "stale" — **marked only, never deleted**, and all old versions are kept.

### Step 0 — First-time setup (once per machine)

```bash
node {baseDir}/scripts/character-refs.mjs config --show
```

If the output ends with "Still missing: …", ask the user these three things, **all at once**:

1. **Which model to use for the main image (anchor)**:
   - `qwen` — Qwen Image 2.1, on your own ComfyUI server. Fast (25–45 seconds per image), exact sizes, uses no subscription quota.
     Needs `COMFY_URL` (optionally `COMFY_USER` / `COMFY_PASS`), put in environment variables or a .env file
   - `codex` — codex built-in image generation (GPT). No API key needed, but it **uses ChatGPT subscription quota** (Plus caps out at about 25 images, recovering after a few hours), 80–160 seconds per image
   - `openai` — the OpenAI Images API, `gpt-image-2` by default. Pay-per-use, needs `OPENAI_API_KEY`; it can also point to a compatible endpoint (`--openai-base-url`)
   - `custom:<name>` — the user's own image-generation command, see `references/models.md`
2. **Which model to use for derived images**: the same as the main image by default. They can be separated (for example a GPT anchor and Qwen derived images)
3. **Whether to stop and wait for human confirmation after generating the anchor**: `yes` recommended — the anchor is the root of the whole set, and if it is wrong, everything after is wasted.
   Choosing `no` lets it through automatically, with "not confirmed by a person" marked in the report; **an anchor that has not passed the check gates is never let through automatically**, and needs a person to look and then `confirm` or regenerate

```bash
node {baseDir}/scripts/character-refs.mjs config --model qwen --confirm-anchor yes --qwen-env-file <.env path>
# Set separately: --anchor-model codex --derive-model qwen
```

The configuration is written to `{baseDir}/config.local.json` (not under version control, and not overwritten on reinstall). From then on it is always used by default,
and when the user says "switch to xx" you re-run `config`. **Do not print passwords or keys from the .env**; `config --show` already masks them.

### Step 1 — One-time input

The user's **one passage** describing the character is enough; do not ask item by item. You (the model) do the splitting:

```bash
node {baseDir}/scripts/character-refs.mjs intake-template
```

Split the description into the fields following the template and write it to `<workdir>/<character name>-intake.json`. The rules (details in `references/intake.md`):

- Fill `lang` with the language the user speaks (Chinese `zh`, English `en` and Japanese `ja` are built in). The confirmation table and report both use this language;
  for other languages, first run `ui-template <lang>`, translate the printed English copy item by item, and put the whole block into the intake's `ui` field
- Mark what the user said as `stated`, what you inferred as `inferred`, and what was filled by convention as `default` — **mark honestly**, because the confirmation table relies on it to remind the user which items to look at
- **If age, gender or era cannot be inferred, ask the user** — only these three may not be made up by you; fill in everything else yourself and do not press with follow-up questions
- `en` goes into the prompt: **always English**, no character name, no art-style words; `text` is for people to read, written in the `lang` language (the `zh` written by old inputs is still recognized)
- Clothing is split into `top` / `bottom` — the headshot uses only the top, and if both top and bottom are given the model pulls the shot back
- **Pick details per character**: those the user names first, and if none, the places that make this character most recognizable, with the default four slots as fallback; facial features do not get a detail image (the headshot already shows them clearly). See `references/intake.md` for details

```bash
node {baseDir}/scripts/character-refs.mjs intake-check <intake.json>
```

If there are problems, fix them as the errors say until it passes. After it passes it prints the **confirmation table**, which you show to the user as is, with inferred and default items marked.
**Only after the user confirms (or edits and then confirms) do you go on.**

### Step 2 — Build the asset

```bash
node {baseDir}/scripts/character-refs.mjs new <intake.json> --out <output directory> [--look style]
```

This builds `<output directory>/<character name>/asset.json`. At this point the whole art-style layer is snapshotted into the asset, and changing a preset later does not affect characters already created.

**Art style**: if the user said one, choose as the user said; if not, it is anime. The characters of one show **all use the same art style**.

| Preset | Names `--look` recognizes |
| --- | --- |
| Anime (default) | `动漫` `卡通` `anime` `cartoon` `二次元` `アニメ` |
| Realistic photo | `写实` `realistic` `photo` `真人` |

`looks` lists all the presets. If the user wants another style (Chinese-ink, American comic…): `look-template <closest preset> > my-look.json`, and change `style` (medium, linework),
`clean` (background and light, **the white background must be kept**), and `neg` (negative words — for a drawn style, take `anime` and `illustration` out of the negative words),
and for a drawn style write `medium` as `drawn`, then `--look my-look.json`. Custom styles have not been tested; generate the anchor first and see.

To switch the style of a character already built:

```bash
node {baseDir}/scripts/character-refs.mjs restyle <asset.json> --look anime
```

After switching, all existing images (the anchor included) are marked stale, the old images are kept, and regeneration starts from the anchor.

### Step 3 — Generate the default tier two

```bash
node {baseDir}/scripts/character-refs.mjs gen <asset.json>
```

With no view and no tier given, it fills in the images in tiers one and two that are not yet generated or that are stale.

If confirmation is configured: this command **generates only the anchor and stops**. Show the image to the user (the report, or open the PNG directly), and once the user says it is fine,

```bash
node {baseDir}/scripts/character-refs.mjs confirm <asset.json>
node {baseDir}/scripts/character-refs.mjs gen <asset.json>      # the same command, continuing with the headshot, profile and back
```

If not satisfied, run `gen <asset.json> front-full` again (producing v2; `--seed` changes the seed, `--model` changes the model),
or go back to Step 1 and change the description. **If the anchor is not confirmed, derived images are refused.** When configured not to confirm, one command produces all four images.

### Step 4 — Move up a tier on demand

```bash
node {baseDir}/scripts/character-refs.mjs gen <asset.json> --tier 3 --reason "E03 has hair-ornament and collar close-ups"
```

`--reason` says why the tier was raised, recorded into the asset. You can also generate only certain images: `gen <asset.json> detail-hair detail-neck`.

### Step 5 — Check and regenerate

```bash
node {baseDir}/scripts/character-refs.mjs check <asset.json>
```

Each image passes the code gates (size 300–5760, aspect ratio 0.4–2.5, proportions right, ≤20MB, background white enough), and then stale status is checked.
**Exit 1 on any problem.** For an image whose gate did not pass or which is stale, regenerate just that one:

```bash
node {baseDir}/scripts/character-refs.mjs gen <asset.json> detail-neck --model codex
```

For the gate "background white enough", full-body images are checked on all four edges, headshots only on the top edge and the upper half of the sides (the body naturally runs into the bottom edge), and detail images are skipped, with that stated plainly.
**The gates cannot check likeness, angle or framing** — always look at the images after generating; these are checked by eye.

### Step 6 — Report

```bash
node {baseDir}/scripts/character-refs.mjs render <asset.json>... --out <output directory>/character-refs.html
```

Several characters can be rendered together. The language defaults to the asset's `lang`, and to switch temporarily add `--lang en`; for a non-built-in language without a `ui`, use `--ui <file>` to pass the self-translated copy,
and missing copy fails immediately, never producing a half-Chinese, half-English report. The UI copy switches language while the character descriptions stay as written.
Tier one has just one card; from tier two it is the model-sheet layout (headshot on the left, front / profile / back at the upper right, a detail strip at the lower right),
and **detail images are not shown by default**, with a one-click toggle on the page. Stale images get a red outline, with a legend at the top of the page, and moving the mouse over a red-outlined image shows the reason; mixed models are flagged.


### Step 7 — Report to the user

One sentence: which images were generated, which model was used, and the report path. Name any whose gates did not pass or that are stale. **Do not say "the result is great" if you have not looked at the images.**

## Final layout

```
<output directory>/
├── character-refs.html          ← render output
└── <character name>/
    ├── asset.json               ← character description + all versions of every image
    └── default/                 ← look (v1 has only the default set)
        ├── front-full.v1.png    ← anchor
        ├── face-front.v1.png
        ├── face-front.v2.png    ← regeneration does not overwrite
        └── detail-hair.v1.png …
```

Every PNG has its identifier written in it (`character/look/view/version`), the model, and which images it referenced, so an image copied away on its own can still be traced to its origin.
For the structure of `asset.json` see `references/schema.md`.

## Boundaries

- The only styles tested are realistic and anime (both run on Qwen through four tiers); the effect of a custom style depends on how it is written, so generate the anchor and see
- Detail images take only what grows on the character (hair ornament, collar, cuff, shoes, accessories); props belong to novel-art
- Known weak spots: small scars tend to be drawn as fresh wounds, large-area details such as double-breasted buttons are framed too far out, Qwen's collar details draw coarse cloth like velvet (regenerate that one with codex), and exposed skin in Qwen detail images comes out too old (an age sentence has been added to the prompt, effective on the 16-year-old sample, not verified at scale)
- The `openai` adapter has had its request format verified only against a local fake server and **has not been run with a real key**; the first time you use it, generate one anchor and look
- The same prompts were tested on both Qwen and GPT; the result of a custom model depends on that model
